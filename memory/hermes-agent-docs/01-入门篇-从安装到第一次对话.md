# 入门篇：从安装到第一次对话

> 5 分钟完成 Hermes Agent 的安装、配置和第一次对话。

**前置要求**：一台安装了 Git 的 Linux / macOS 机器（Windows 需 WSL2），一个 LLM API Key
**预计时间**：5–10 分钟
**官方文档**：[Installation](https://hermes-agent.nousresearch.com/docs/getting-started/installation) · [Quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart) · [CLI](https://hermes-agent.nousresearch.com/docs/user-guide/cli) · [Configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)

## 你将学到

- 用一行命令完成 Hermes Agent 安装
- 配置 LLM Provider 并启动第一次对话
- 使用 CLI 的核心功能（slash commands、session resume、多行输入）
- 理解配置文件 `~/.hermes/` 的目录结构和基本用法
- 与 OpenClaw 的关键差异对比

## 1. 安装

### 快速安装（推荐）

Hermes Agent 提供一行命令的自动安装器，会自动处理所有依赖（Python、Node.js、ripgrep、ffmpeg）。

```bash
# 本地终端 — Linux / macOS / WSL2
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

安装完成后重新加载 shell：

```bash
source ~/.bashrc   # 或: source ~/.zshrc
```

> **Windows 用户**：Hermes Agent 不支持原生 Windows。请先安装 [WSL2](https://learn.microsoft.com/en-us/windows/wsl/install)，然后在 WSL2 终端中执行上述命令。
>
> **Android / Termux**：安装器会自动检测 Termux 环境，使用 `pkg` 安装系统依赖。详见 [Termux guide](https://hermes-agent.nousresearch.com/docs/getting-started/termux)。

### 安装器做了什么

安装器自动完成以下步骤（来源：[Installation — What the Installer Does](https://hermes-agent.nousresearch.com/docs/getting-started/installation)）：

- 安装 `uv`（Python 包管理器）
- 通过 `uv` 安装 Python 3.11（无需 sudo）
- 安装 Node.js v22（用于 browser automation）
- 克隆 Hermes Agent 仓库
- 创建虚拟环境并安装所有 Python 依赖
- 创建全局 `hermes` 命令
- 运行 LLM Provider 配置向导

### 手动安装

如果你需要完全控制安装过程，可以手动安装。核心步骤如下：

```bash
# 本地终端

# 1. 安装 uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# 2. 克隆仓库
git clone --recurse-submodules https://github.com/NousResearch/hermes-agent.git
cd hermes-agent

# 3. 创建虚拟环境
uv venv venv --python 3.11
export VIRTUAL_ENV="$(pwd)/venv"

# 4. 安装依赖（全部扩展）
uv pip install -e ".[all]"

# 5. 安装 Node.js 依赖（可选，用于 browser 和 WhatsApp）
npm install

# 6. 创建配置目录
mkdir -p ~/.hermes/{cron,sessions,logs,memories,skills,pairing,hooks,image_cache,audio_cache,whatsapp/session}
cp cli-config.yaml.example ~/.hermes/config.yaml
touch ~/.hermes/.env

# 7. 添加 API Key
echo 'OPENROUTER_API_KEY=sk-or-v1-your-key' >> ~/.hermes/.env

# 8. 全局链接 hermes 命令
mkdir -p ~/.local/bin
ln -sf "$(pwd)/venv/bin/hermes" ~/.local/bin/hermes

# 如果 ~/.local/bin 不在 PATH 中
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
```

可选的 extras 按需安装（来源：[Installation — Manual Installation](https://hermes-agent.nousresearch.com/docs/getting-started/installation)）：

| Extra | 用途 | 安装命令 |
|-------|------|---------|
| `messaging` | Telegram / Discord / Slack gateway | `uv pip install -e ".[messaging]"` |
| `cron` | 定时任务（cron 表达式解析） | `uv pip install -e ".[cron]"` |
| `voice` | 语音输入 + TTS 播放 | `uv pip install -e ".[voice]"` |
| `mcp` | Model Context Protocol 支持 | `uv pip install -e ".[mcp]"` |
| `acp` | ACP 编辑器集成 | `uv pip install -e ".[acp]"` |

可以组合安装：`uv pip install -e ".[messaging,cron]"`

### 验证安装

```bash
# 本地终端
hermes version    # 检查命令是否可用
hermes doctor     # 运行诊断，验证一切正常
hermes status     # 查看当前配置状态
```

### 常见安装问题

| 问题 | 解决方法 |
|------|---------|
| `hermes: command not found` | 重新加载 shell：`source ~/.bashrc`，或检查 PATH |
| API key 未设置 | 运行 `hermes model` 配置 Provider，或 `hermes config set OPENROUTER_API_KEY your_key` |
| 更新后配置缺失 | 运行 `hermes config check` 然后 `hermes config migrate` |

## 2. 第一次对话

安装完成并配置好 API Key 后，启动对话只需一条命令：

```bash
# 本地终端
hermes
```

你会看到一个欢迎 banner，显示当前使用的 model、可用的 tools 和 skills。然后直接输入消息开始对话：

```
❯ What can you help me with?
```

> **最小上下文要求**：Hermes Agent 要求模型至少支持 64K token 的上下文窗口。大多数主流模型（Claude、GPT、Gemini、Qwen、DeepSeek）都满足此要求。如果你使用本地模型，需确保设置上下文大小 ≥ 64K（例如 `--ctx-size 65536` for llama.cpp）。（来源：[Quickstart — Minimum context](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)）

### 非交互式单次查询

如果你不想进入交互式 TUI，可以直接发送单条消息：

```bash
# 本地终端
hermes chat -q "Hello! What tools do you have available?"
```

### 切换 Provider 和 Model

```bash
# 本地终端 — 交互式选择 Provider 和 Model
hermes model

# 单次查询指定 model
hermes chat --model "anthropic/claude-sonnet-4"

# 指定 provider
hermes chat --provider nous       # 使用 Nous Portal
hermes chat --provider openrouter # 强制使用 OpenRouter
```

Hermes Agent 支持 20+ Provider（来源：[Quickstart — Set Up a Provider](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)）：

| Provider | 说明 | 设置方式 |
|----------|------|---------|
| Nous Portal | 订阅制，零配置 | OAuth 登录 `hermes model` |
| Anthropic | Claude 模型 | API Key 或 Claude Code auth |
| OpenRouter | 多 Provider 路由 | 输入 API Key |
| OpenAI Codex | ChatGPT OAuth | Device code auth |
| DeepSeek | DeepSeek 直连 | `DEEPSEEK_API_KEY` |
| 阿里云 | 通义千问 via DashScope | `DASHSCOPE_API_KEY` |
| Hugging Face | 20+ 开源模型 | `HF_TOKEN` |
| Custom Endpoint | VLLM / SGLang / Ollama 等 | 设置 base URL + API Key |

随时可以切换，不锁定。`hermes model` 重新选择即可。

## 3. CLI 基本用法

Hermes Agent 的 CLI 是一个完整的 Terminal User Interface (TUI)，不是 Web UI。（来源：[CLI Interface](https://hermes-agent.nousresearch.com/docs/user-guide/cli)）

### Status Bar

界面上方有一个持久状态栏，实时显示：

```
⚗ claude-sonnet-4-20250514 │ 12.4K/200K │ [██████░░░░] 6% │ $0.06 │ 15m
```

- **Model name**：当前模型
- **Token count**：已用 / 最大上下文 token
- **Context bar**：可视化填充指示（< 50% 绿色，50–80% 黄色，80–95% 橙色，≥ 95% 红色）
- **Cost**：预估费用
- **Duration**：会话已用时间

### 核心快捷键

| 按键 | 功能 |
|------|------|
| `Enter` | 发送消息 |
| `Alt+Enter` 或 `Ctrl+J` | 多行输入（换行） |
| `Ctrl+C` | 中断 agent（2 秒内按两次强制退出） |
| `Ctrl+D` | 退出 |
| `Ctrl+Z` | 挂起到后台（`fg` 恢复） |
| `Tab` | 接受自动补全建议 |
| `Ctrl+B` | 语音录音（需启用 voice mode） |

### Slash Commands

输入 `/` 会弹出自动补全下拉菜单。常用命令（来源：[CLI — Slash Commands](https://hermes-agent.nousresearch.com/docs/user-guide/cli)）：

| 命令 | 功能 |
|------|------|
| `/help` | 显示所有可用命令 |
| `/model` | 查看或切换当前 model |
| `/tools` | 列出当前可用的 tools |
| `/skills browse` | 浏览 Skills Hub |
| `/personality pirate` | 切换 agent 人格 |
| `/title My Session` | 给当前会话命名 |
| `/reasoning high` | 提高推理强度 |
| `/voice on` | 启用语音模式 |
| `/background <prompt>` | 后台运行 prompt |

> 命令不区分大小写：`/HELP` 和 `/help` 效果相同。

### 中断和重定向

如果 agent 执行时间过长，直接输入新消息并按 Enter——它会中断当前任务，转而处理你的新指令。在 CLI 中这叫 **Busy Input Mode**，可在 `interrupt`（默认）和 `queue`（排队等待）之间切换（来源：[CLI — Interrupting the Agent](https://hermes-agent.nousresearch.com/docs/user-guide/cli)）：

```yaml
# ~/.hermes/config.yaml
display:
  busy_input_mode: "queue"  # 或 "interrupt"（默认）
```

### 会话恢复（Session Resume）

退出 CLI 时，Hermes 会打印恢复命令：

```
Resume this session with:
  hermes --resume 20260225_143052_a1b2c3
```

```bash
# 本地终端 — 恢复最近的会话
hermes --continue    # 或: hermes -c

# 恢复指定会话
hermes --resume 20260225_143052_a1b2c3   # 或: hermes -r <session_id>

# 按名称恢复
hermes --resume "refactoring auth"
```

会话存储在 `~/.hermes/state.db`（SQLite），恢复时完整加载历史消息、tool calls 和 responses。（来源：[CLI — Session Storage](https://hermes-agent.nousresearch.com/docs/user-guide/cli)）

### 后台任务

在 CLI 中可以让 agent 后台执行任务，同时你继续做别的事：

```
/background Analyze the logs in /var/log and summarize any errors from today
```

完成后结果会以面板形式显示在终端中。多个后台任务可并行运行，每个有独立 ID。

### 启动时预加载 Skills

```bash
# 本地终端
hermes -s hermes-agent-dev,github-auth
hermes chat -s github-pr-workflow -q "open a draft PR"
```

### 工具执行进度

CLI 在 agent 工作时显示动画反馈：

```
┊ 💻 terminal `ls -la` (0.3s)
┊ 🔍 web_search (1.2s)
┊ 📄 web_extract (2.1s)
```

用 `/verbose` 循环切换显示模式：`off` → `new` → `all` → `verbose`。

## 4. 配置文件基础

### 目录结构

所有配置存储在 `~/.hermes/` 目录下（来源：[Configuration — Directory Structure](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)）：

```
~/.hermes/
├── config.yaml      # 主配置文件（model、terminal、TTS、compression 等）
├── .env             # API keys 和 secrets
├── auth.json        # OAuth 凭证（Nous Portal 等）
├── SOUL.md          # 主要 agent 身份定义（系统 prompt slot #1）
├── memories/        # 持久化记忆（MEMORY.md、USER.md）
├── skills/          # Agent 创建的 skills
├── cron/            # 定时任务
├── sessions/        # Gateway 会话
└── logs/            # 日志（secrets 自动脱敏）
```

### 管理配置

```bash
# 本地终端
hermes config              # 查看当前配置
hermes config edit         # 在编辑器中打开 config.yaml
hermes config set KEY VAL  # 设置单个值
hermes config check        # 检查缺失选项（更新后使用）
hermes config migrate      # 交互式添加缺失选项
```

> `hermes config set` 自动将值路由到正确文件——API keys 存入 `.env`，其他存入 `config.yaml`。

### 配置优先级

设置按以下顺序解析（优先级从高到低，来源：[Configuration — Configuration Precedence](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)）：

1. **CLI 参数** — `hermes chat --model anthropic/claude-sonnet-4`
2. **`~/.hermes/config.yaml`** — 非 secret 设置的主配置
3. **`~/.hermes/.env`** — API keys、tokens、passwords
4. **内置默认值** — 未设置时的 fallback

**原则**：Secrets 放 `.env`，其他放 `config.yaml`。

### 环境变量替换

`config.yaml` 中可以用 `${VAR_NAME}` 语法引用环境变量：

```yaml
# ~/.hermes/config.yaml
auxiliary:
  vision:
    api_key: ${GOOGLE_API_KEY}
    base_url: ${CUSTOM_VISION_URL}
```

### 关键配置项速览

以下是一些初学者最可能用到的配置项（来源：[Configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)）：

**Terminal 后端** — 控制 agent 命令在哪里执行：

```yaml
# ~/.hermes/config.yaml
terminal:
  backend: local    # local（默认）| docker | ssh | modal | daytona | singularity
  timeout: 180      # 单命令超时（秒）
```

- `local`：直接在本机执行，无隔离
- `docker`：Docker 容器内执行，安全隔离（需安装 Docker）
- `ssh`：远程服务器执行

**Context Compression** — 长对话自动摘要：

```yaml
# ~/.hermes/config.yaml
compression:
  enabled: true
  threshold: 0.50    # 达到上下文 50% 时触发压缩
```

**Display** — 界面显示设置：

```yaml
# ~/.hermes/config.yaml
display:
  tool_progress: all        # off | new | all | verbose
  streaming: false          # 是否实时流式输出
  show_reasoning: false     # 是否显示模型推理过程
  bell_on_complete: false   # 任务完成时响铃
```

**Quick Commands** — 自定义快捷命令，不消耗 token：

```yaml
# ~/.hermes/config.yaml
quick_commands:
  status:
    type: exec
    command: systemctl status hermes-agent
  gpu:
    type: exec
    command: nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv,noheader
```

使用时输入 `/status` 或 `/gpu`，直接执行 shell 命令，不经过 LLM。

**Timezone** — 覆盖服务器本地时区：

```yaml
# ~/.hermes/config.yaml
timezone: "Asia/Shanghai"  # IANA 时区标识符
```

### Quick Reference

| 命令 | 功能 |
|------|------|
| `hermes` | 开始对话 |
| `hermes model` | 选择 LLM Provider 和 model |
| `hermes tools` | 配置启用的 tools |
| `hermes setup` | 完整设置向导 |
| `hermes doctor` | 诊断问题 |
| `hermes update` | 更新到最新版本 |
| `hermes gateway` | 启动消息网关 |
| `hermes --continue` | 恢复上次会话 |

## 横向对比：Hermes Agent vs OpenClaw

| 维度 | Hermes Agent | OpenClaw |
|------|-------------|----------|
| **定位** | 开源 AI Agent，终端优先，技能自进化 | 个人 AI 助手框架，多渠道集成 |
| **安装方式** | 一行 `curl \| bash`，自动装依赖 | npm 全局安装 `npm i -g openclaw` |
| **交互界面** | TUI（终端用户界面），支持流式输出 | 无内置 TUI，通过消息渠道交互 |
| **CLI 命令** | `hermes` 为主命令，子命令丰富 | `openclaw` 为主命令 |
| **会话管理** | SQLite 持久化，`--continue` / `--resume` | 基于文件 + transcript 系统 |
| **Skills 生态** | Skills Hub + `hermes skills install` | AgentSkill 格式 + 本地/云端搜索 |
| **Provider 支持** | 20+ Provider（含 Nous Portal、Codex、HF） | 通过 model string 路由 |
| **终端隔离** | 6 种 backend（local/docker/ssh/modal/daytona/singularity） | exec 直连本机 |
| **MCP 支持** | 原生 `[mcp]` extra | 原生 MCP tool 集成 |
| **配置文件** | `~/.hermes/config.yaml` + `.env` | `~/.openclaw/openclaw.json` |

> 以上对比基于两者官方文档，不代表完整功能对比。Hermes Agent 偏向"终端内的全能 Agent"，OpenClaw 偏向"多渠道个人 AI 助手"。

## 常见问题 / 踩坑

### 1. 安装后 `hermes` 命令找不到

```bash
# 本地终端
source ~/.bashrc   # 或 source ~/.zshrc
# 如果仍然找不到，检查 PATH
echo $PATH | tr ':' '\n' | grep -i local
# 如果 ~/.local/bin 不在 PATH 中
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
```

### 2. 模型上下文不足 64K

Hermes Agent 启动时会校验模型上下文窗口大小，小于 64K 的模型会被拒绝（来源：[Quickstart — Minimum context](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)）。本地模型解决方案：

```bash
# llama.cpp
--ctx-size 65536

# Ollama
-c 65536
```

### 3. Docker 后端不可用

如果 `hermes doctor` 报告 Docker 问题：

```bash
# 本地终端
docker version   # 验证 Docker 是否正常
# 如果 Docker 未安装，先切回 local 后端
hermes config set terminal.backend local
```

### 4. 更新后配置缺失

```bash
# 本地终端
hermes config check     # 检查缺失选项
hermes config migrate   # 交互式补全缺失配置
```

### 5. 压缩摘要模型上下文不够

压缩器会将完整对话中间部分发送给摘要模型。如果摘要模型的上下文窗口比主模型小，摘要会失败，中间消息被静默丢弃（来源：[Configuration — Context Compression](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)）。解决方案：确保 `auxiliary.compression.model` 的上下文窗口 ≥ 主模型。

### 6. 权限 / API Key 问题

```bash
# 本地终端 — 查看当前配置
hermes config
# 重新设置 key
hermes config set OPENROUTER_API_KEY sk-or-v1-your-new-key
```
