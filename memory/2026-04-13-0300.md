session end hook 和memoryflush hook有什么区别
assistant: 好问题，先说结论：**OpenClaw 目前没有原生的 session end hook 或 memory flush hook**，这两个是我的构想，不是现有能力。

但可以从概念上区分：

---

**Session End Hook（会话结束钩子）**
- 触发时机：用户停止发消息、会话超时关闭时
- 做的事：写 daily note、总结本次会话干了什么
- 问题：OpenClaw 没有"会话结束"的明确信号，无法可靠触发

---

**Memory Flush Hook（记忆刷新钩子）**
- 触发时机：每次 agent 回复后，或达到一定轮次后
- 做的事：把本轮对话的关键信息写入文件
- 问题：同样没有原生支持，且频率太高会浪费 token

---

**我们实际能用的方案：**

| 方案 | 可行性 | 说明 |
|------|--------|------|
| 主动约定 | ✅ 现在就能用 | 你说"今天结束了"，我写 daily note |
| HEARTBEAT 触发写入 | ✅ 有限可行 | 心跳时检查今天有没有写，没写补一条 |
| Cron 定时写摘要 | ✅ 最可靠 | 比如每天 22:00 跑一个任务，扫 transcript 写 daily note |
| Session end hook | ❌ 不支持 | OpenClaw 无此能力 |

---

**最务实的方案**：加一个 **22:00 的 cron**，扫昨天的 transcript JSONL，自动生成 daily note 写入文件。这样复盘信息源就从"靠人写"变成"机器自动生成"，最可靠。

- 每次 compaction 周期只触发一次
- prompt 可自定义
