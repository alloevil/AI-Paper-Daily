## 1. Hermes Agent 是什么

### 高层定位

Hermes Agent 是 Nous Research 打造的**开源、自托管、模型无关**的个人 AI Agent。它的核心设计理念可以用一句话概括：

> **The agent that grows with you.** — 跟你一起成长的 Agent。

与 ChatGPT/Claude 等对话式 AI 不同，Hermes 不只是一个"聊天窗口"。它是一个**持久运行的进程**，拥有自己的记忆系统、工具链、定时任务和学习回路。你可以从 Telegram 发消息给它，它在云端 VM 上跑着代码；你关掉手机，它继续执行 Cron 任务。

### 核心价值主张

| 特性 | 说明 |
|------|------|
| **自托管** | 跑在你的机器上（$5 VPS 或 GPU 集群），数据不出服务器 |
| **模型无关** | 支持 200+ 模型（OpenRouter、OpenAI、Anthropic、小米 MiMo、GLM 等），随时切换 |
| **跨平台** | CLI + 18 个消息平台（Telegram、Discord、Slack、WhatsApp、Signal、飞书等） |
| **自进化** | 内置 RL 训练管线、自动 Skill 创建、经验记忆 |
| **持久运行** | Session 管理 + Cron 调度 + 后台进程，不需要你盯着 |

## 2. 系统架构

### 2.1 全景概览

Hermes Agent 的代码库大约 **10,700 行核心代码**（`run_agent.py`），加上 CLI（~10,000 行）和 Gateway（~9,000 行），是一个中等规模但设计紧凑的 Python 项目。

```
┌─────────────────────────────────────────────────────────┐
│  入口层                                                  │

        │             │                    │
        ▼             ▼                    ▼
┌─────────────────────────────────────────────────────────┐

│                                                         │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐    │
│  │ Prompt       │ │ Provider     │ │ Tool         │    │

│  └──────┬───────┘ └──────┬───────┘ └──────┬───────┘    │
│  ┌──────┴───────┐ ┌──────┴───────┐ ┌──────┴───────┐    │
```

### 2.2 Agent Loop — 核心引擎

`AIAgent`（`run_agent.py`，约 10,700 行）是整个系统的"大脑"。它负责：

1. **Prompt 组装**：从 `SOUL.md`、`MEMORY.md`、`USER.md`、Skills、上下文文件中拼装系统提示词
2. **Provider 选择**：根据配置将 `(provider, model)` 映射为 `(api_mode, api_key, base_url)`
3. **可中断的 API 调用**：在后台线程中发起 HTTP 请求，主线程监听中断信号
4. **工具执行**：单工具串行、多工具并发（ThreadPoolExecutor）
5. **上下文压缩**：对话超过上下文窗口 50% 时自动摘要
6. **故障转移**：主模型失败时按 `fallback_providers` 列表逐个尝试

每个 Agent Loop 的一轮（turn）遵循以下生命周期：

```
用户输入
  → 附加到对话历史
  → 构建 / 复用缓存的系统提示词
  → 检查是否需要预压缩（>50% 上下文）
  → 格式化为 API 消息
  → 发起可中断的 API 调用
  → 解析响应：
      如果有 tool_calls → 执行工具 → 回到格式化步骤
      如果是文本响应 → 持久化会话 → 返回
```

**消息交替规则**：Hermes 强制执行严格的角色交替（User → Assistant → User），不允许连续两个 Assistant 或两个 User 消息。Tool 角色允许连续（并行工具结果）。

**可中断 API 调用**的设计值得注意：API 请求在后台线程中执行，主线程同时监听中断事件。当用户发送新消息、执行 `/stop` 命令或收到信号时，API 线程被丢弃（响应作废），Agent 可以立即处理新输入或干净关闭 —— 不会有部分响应被注入对话历史。

### 2.3 三种 API 模式

Hermes 支持三种 API 调用方式，全部统一到内部 OpenAI 格式的消息结构：

| API 模式 | 适用场景 | 客户端类型 |
|----------|---------|-----------|
| `chat_completions` | OpenAI 兼容端点（OpenRouter、自定义等大多数 provider） | `openai.OpenAI` |
| `codex_responses` | OpenAI Codex / Responses API | `openai.OpenAI`（Responses 格式） |
| `anthropic_messages` | Anthropic 原生 Messages API | `anthropic.Anthropic`（适配器转换） |

模式解析优先级：显式参数 > Provider 特定检测 > Base URL 启发式 > 默认 `chat_completions`。

**设计意义**：三种模式的输入输出格式不同，但 Agent 内部始终使用统一的 OpenAI 格式消息。API 调用前做格式转换，响应后做反向转换 —— Agent Loop 完全不感知外部 API 的差异。

### 2.4 Provider 解析

`runtime_provider.py` 负责将用户的 provider/model 选择解析为实际的 API 调用参数。它支持 **18+ 个 Provider**，处理 OAuth 流程、凭证池、别名解析等。所有入口（CLI、Gateway、Cron、ACP、辅助调用）共用同一个解析器。

辅助任务（视觉分析、上下文压缩、网页提取、会话搜索）各有独立的 fallback 链，可通过 `auxiliary.*` 配置独立设置。

### 2.5 会话存储

Hermes 使用 **SQLite + FTS5 全文检索** 存储会话数据（`hermes_state.py`）。关键特性：

- **Session Lineage（会话血缘）**：压缩时创建"子 Session"，保留父子关系，可通过 `/resume` 恢复
- **平台隔离**：每个平台的会话独立存储
- **原子写入**：处理并发写入的竞争条件
- **FTS5 搜索**：`session_search` 工具支持跨会话全文检索 + LLM 摘要

## 3. 模型与训练

### 3.1 模型无关架构

Hermes 不绑定任何特定模型。通过 Provider 系统，你可以使用：

- **Nous Portal**（Nous Research 自有平台）
- **OpenRouter**（200+ 模型）
- **小米 MiMo**、**GLM/z.ai**、**Kimi/Moonshot**、**MiniMax**
- **OpenAI**、**Anthropic**、**HuggingFace**
- **自定义端点**（任何 OpenAI 兼容 API）

切换模型只需一行命令，无需改代码：

```bash
# 本地终端
hermes model                    # 交互式选择
hermes model openrouter:claude-4-sonnet  # 直接指定
```

### 3.2 RL 训练管线

Hermes Agent 内置了完整的 **RL（强化学习）训练管线**，这是它与所有其他 AI Agent 框架的核心差异化能力。基于 **Tinker-Atropos** 框架构建。

#### 三大组件

| 组件 | 角色 |
|------|------|
| **Atropos** | 轨迹 API 服务器：协调环境交互、管理 rollout 组、计算 advantage |
| **Tinker** | 训练服务：处理模型权重、LoRA 训练、采样/推理、优化器步骤 |
| **Environments** | Python 任务类：定义任务、评分和奖励函数（如 GSM8K 数学题） |

#### 训练算法

使用 **GRPO（Group Relative Policy Optimization）** + **LoRA 适配器**。训练循环：

1. 从 Atropos 获取一批 rollout（prompt + completions + scores）
2. 转换为 Tinker Datum 对象（带 padding logprobs 和 advantages）
3. 执行 forward-backward pass（importance sampling loss）
4. Adam 优化器步骤（lr=4e-5, β1=0.9, β2=0.95）
5. 保存权重，创建新的 sampling client 用于下一步推理
6. 记录指标到 WandB

#### 训练工具

Hermes 提供了一套 `rl_*` 工具，让你通过对话就能操作训练：

| 工具 | 用途 |
|------|------|
| `rl_list_environments` | 发现可用的 RL 环境（AST 扫描找到继承 `BaseEnv` 的类） |
| `rl_select_environment` | 选择环境并加载配置 |
| `rl_get_current_config` | 查看可配置和锁定的字段 |
| `rl_edit_config` | 修改训练参数（group_size、batch_size、wandb_name 等） |
| `rl_start_training` | 启动训练（生成 3 个进程） |
| `rl_check_status` | 监控训练进度和 WandB 指标（每 30 分钟限一次） |
| `rl_stop_training` | 停止训练任务 |
| `rl_get_results` | 获取最终指标和模型权重路径 |
| `rl_list_runs` | 列出所有活跃和完成的训练任务 |
| `rl_test_inference` | 推理测试（无需 Tinker API，仅需 OpenRouter key） |

#### 训练启动流程

`rl_start_training()` 会生成 3 个进程，按延迟顺序启动（确保初始化顺序）：

1. **Atropos API server**（`run-api`）— 轨迹协调，延迟 0s
2. **Tinker trainer**（`launch_training.py`）— LoRA 训练 + FastAPI 推理服务（端口 8001），延迟 5s
3. **Environment**（`environment.py serve`）— 选定的环境连接到 Atropos，延迟 35s

#### 推理测试

在启动完整训练之前，可以用 `rl_test_inference` 验证环境是否正常工作。默认配置：

- 3 步 × 16 completions = 每个模型 48 个 rollout
- 测试 3 个不同规模的模型：`qwen/qwen3-8b`（小）、`z-ai/glm-4.7-flash`（中）、`minimax/minimax-m2.7`（大）
- 总计约 144 个 rollout

#### 自定义环境

你可以创建自己的 RL 环境。只需：

1. 在 `tinker-atropos/tinker_atropos/environments/` 创建 Python 文件
2. 继承 `BaseEnv` 类
3. 实现 `load_dataset()`、`get_next_item()`、`score_answer()`、`collect_trajectories()`
4. Agent 可以帮你完成 —— 它能读取现有环境文件、检查 HuggingFace 数据集、编写新环境代码

#### 前置条件

```bash
# 本地终端 — 设置 API keys
hermes config set TINKER_API_KEY your-tinker-key
hermes config set WANDB_API_KEY your-wandb-key
```

需要 Python >= 3.11（Tinker 包要求）。当两个 key 都存在且 Python 版本满足要求时，`rl` 工具集自动启用。

### 3.3 自我进化闭环

Hermes 的"成长"不只是 RL 训练。它有一个完整的**自进化回路**：

1. **经验记忆**：复杂任务完成后自动创建 Skill
2. **Skill 自优化**：Skill 在使用过程中自我改进
3. **定期知识整理**：自动将对话中的洞察持久化到 `MEMORY.md`
4. **跨会话检索**：FTS5 全文搜索 + LLM 摘要，回忆过去的对话
5. **用户建模**：通过 Honcho 辩证模型构建用户画像

> 这就是 "The agent that grows with you" 的真正含义 —— Agent 不只是记住你告诉它的东西，它还从经验中学习并主动改进自己。

## 4. 扩展生态

### 4.1 工具系统架构

Hermes 的工具系统基于**自注册 + 中心化分发**模式：

```
tools/registry.py (无依赖 — 所有工具文件导入它)
  ↑
tools/*.py (每个文件在导入时调用 registry.register())
  ↑
model_tools.py (导入 tools/registry + 触发工具发现)
  ↑
run_agent.py, cli.py, batch_runner.py, environments/
```

**关键设计**：工具注册发生在**导入时**，在任何 Agent 实例创建之前。任何包含顶层 `registry.register()` 调用的 `tools/*.py` 文件都会被自动发现 —— 无需手动维护导入列表。

工具发现使用 **AST 解析**扫描 `tools/` 目录，找到包含顶层 `registry.register()` 调用的模块后才导入它们（避免导入辅助模块）。之后 MCP 工具和 Plugin 工具也被发现并注册。

### 4.2 工具分发与执行

当模型返回 `tool_call` 时，分发流程：

1. `run_agent.py` Agent Loop 捕获 tool_call
2. `model_tools.handle_function_call()` 接管
3. **Agent 级工具**（todo、memory、session_search、delegate_task）被拦截，直接由 Agent Loop 处理
4. 其他工具经过 **Plugin pre-hook** → **registry.dispatch()** → **Plugin post-hook**
5. 双层错误包装确保模型始终收到合法 JSON

### 4.3 工具可用性检查

每个工具可以提供 `check_fn`，返回 True/False 表示是否可用：

- API key 是否存在
- 服务是否运行
- 二进制是否已安装

构建模型 schema 时会运行 `check_fn()`，不可用的工具从 schema 中移除，模型根本看不到它们。异常处理是 fail-safe 的 —— `check_fn` 抛异常等同于不可用。

### 4.4 Plugin 系统

三种发现来源：

| 来源 | 路径 |
|------|------|
| 用户插件 | `~/.hermes/plugins/` |
| 项目插件 | `.hermes/plugins/` |
| pip 入口点 | 通过 `pip install` 安装的插件 |

插件通过 context API 注册工具、钩子和 CLI 命令。两种特殊插件类型：

- **Memory Provider**：可插拔的记忆后端（同一时间只能激活一个）
- **Context Engine**：可插拔的上下文压缩引擎（同一时间只能激活一个）

### 4.5 技能（Skills）生态

- **内置 Skills**：`skills/` 目录，始终可用
- **可选 Skills**：`optional-skills/` 目录，需显式安装
- **社区 Skills**：通过 Skills Hub 安装，带安全扫描（Skills Guard）
- **自创建 Skills**：Agent 在复杂任务后自动创建，也可手动编写
- 兼容 [agentskills.io](https://agentskills.io) 开放标准

## 5. 安全模型

Hermes 采用**纵深防御（Defense-in-Depth）**安全模型，共七层：

### 第 1 层：用户授权

Gateway 通过分层授权控制谁可以与 Agent 交互（检查顺序）：

1. 平台级 allow-all 标志（如 `DISCORD_ALLOW_ALL_USERS=true`）
2. DM Pairing 批准列表
3. 平台特定白名单（如 `TELEGRAM_ALLOWED_USERS=123,456`）
4. 全局白名单（`GATEWAY_ALLOWED_USERS`）
5. 全局 allow-all（`GATEWAY_ALLOW_ALL_USERS=true`）
6. **默认拒绝**

### 第 2 层：危险命令审批

`tools/approval.py` 维护一套正则表达式模式，匹配危险命令。覆盖场景包括：

- 递归删除（`rm -r`）、根路径删除
- 世界可写权限（`chmod 777`）
- 格式化磁盘（`mkfs`）、磁盘复制（`dd if=`）
- SQL DROP / DELETE without WHERE / TRUNCATE
- 系统服务停止（`systemctl stop`）
- Fork bomb、`kill -9 -1`
- Shell 执行（`bash -c`、`curl | sh`）
- 敏感文件覆盖（`> /etc/`、`> ~/.ssh/`）

三种审批模式：

| 模式 | 行为 |
|------|------|
| `manual`（默认） | 始终提示用户审批 |
| `smart` | 辅助 LLM 评估风险，低风险自动通过，高风险自动拒绝 |
| `off` | 禁用所有审批（等同 `--yolo`） |

CLI 审批界面提供四种选项：**once**（本次通过）、**session**（本会话通过）、**always**（永久白名单）、**deny**（拒绝，默认）。超时默认 60 秒，超时后 fail-closed（拒绝）。

### 第 3 层：容器隔离

使用 Docker、Singularity、Modal、Daytona 运行工具时，容器本身是安全边界：

- 所有 Linux capabilities 被丢弃
- 禁止特权提升
- PID 限制
- 容器内的危险命令检查被跳过（因为容器已隔离）

### 第 4 层：MCP 凭证过滤

MCP 子进程的环境变量被隔离，防止凭证泄露到外部工具服务器。

### 第 5 层：上下文文件扫描

项目文件（`.hermes.md`、`AGENTS.md`）在加载时进行**提示词注入检测**，扫描 instruction-override 模式。

### 第 6 层：跨会话隔离

Session 之间无法互相访问数据或状态。Cron Job 的存储路径经过硬化处理，防止路径遍历攻击。

### 第 7 层：输入净化

终端工具后端的工作目录参数经过白名单验证，防止 shell 注入。所有用户输入在拼入 shell 命令前使用 `shlex.quote()` 转义。路径检查使用 `os.path.realpath()` 防止 symlink 绕过。

## 6. 贡献指南

### 6.1 贡献优先级

Nous Research 对贡献的重视程度排序：

1. **Bug 修复** — 崩溃、错误行为、数据丢失
2. **跨平台兼容** — macOS、不同 Linux 发行版、WSL2
3. **安全加固** — Shell 注入、提示词注入、路径遍历
4. **性能和鲁棒性** — 重试逻辑、错误处理、优雅降级
5. **新 Skills** — 广泛有用的 Skill
6. **新工具** — 少见；大多数能力应该是 Skill
7. **文档** — 修正、澄清、新示例

> 注意这个排序：**Bug 修复和安全 > 新功能**。这是成熟开源项目的标志。官方文档原话："Before writing a tool, ask yourself: should this be a skill instead?"

### 6.2 开发环境搭建

```bash
# 本地终端
# 克隆仓库（含子模块）
git clone --recurse-submodules https://github.com/NousResearch/hermes-agent.git
cd hermes-agent

# 创建 Python 3.11 虚拟环境
uv venv venv --python 3.11
export VIRTUAL_ENV="$(pwd)/venv"

# 安装所有依赖
uv pip install -e ".[all,dev]"
uv pip install -e "./tinker-atropos"

# 可选：浏览器工具
npm install

# 配置开发环境
mkdir -p ~/.hermes/{cron,sessions,logs,memories,skills}
cp cli-config.yaml.example ~/.hermes/config.yaml
echo 'OPENROUTER_API_KEY=sk-or-v1-your-key' >> ~/.hermes/.env

# 全局命令
mkdir -p ~/.local/bin
ln -sf "$(pwd)/venv/bin/hermes" ~/.local/bin/hermes

# 验证
hermes doctor
hermes chat -q "Hello"

# 运行测试（3000+ 测试用例）
pytest tests/ -v
```

### 6.3 代码规范

| 规则 | 说明 |
|------|------|
| PEP 8 | 实用主义，不严格限制行宽 |
| 注释 | 只解释非显而易见的意图、权衡、API 陷阱 |
| 错误处理 | 捕获特定异常，意外错误用 `logger.error()` + `exc_info=True` |
| 跨平台 | 不假设 Unix — `termios`/`fcntl` 需捕获 `ImportError` + `NotImplementedError` |
| 路径安全 | 用 `get_hermes_home()` 代替硬编码 `~/.hermes` |
| 文件编码 | `.env` 加载需处理非 UTF-8 编码（fallback `latin-1`） |
| 进程管理 | `os.setsid()` 需检查 `platform.system() != "Windows"` |

## 7. 横向对比与总结

### 7.1 架构设计差异

| 维度 | Hermes Agent | OpenClaw | Claude Code |
|------|-------------|----------|-------------|
| **定位** | 自托管个人 Agent | 开源 Agent 平台 | Anthropic 官方 CLI Agent |
| **代码规模** | ~30K 行 Python | ~40K 行 TypeScript | 闭源 |
| **模型绑定** | 模型无关（200+ 模型） | 多模型支持 | Claude 系列专属 |
| **Agent Loop** | 同步编排（AIAgent，单一类 ~10.7K 行） | 事件驱动 + 子 Agent | 单一 Claude 对话 |
| **工具系统** | 自注册 + AST 发现（47 工具 / 19 工具集） | Tool + Skill 双层 | 内置工具集 |
| **消息平台** | 18 个适配器 | 8+ 个适配器 | 无（纯 CLI） |
| **记忆系统** | 分层记忆 + FTS5 + Honcho 用户建模 | 文件记忆 + Wiki | 会话内上下文 |
| **RL 训练** | ✅ 内置 Atropos + Tinker（GRPO + LoRA） | ❌ | ❌ |
| **自进化** | ✅ Skill 自创建 + 自优化 + 经验记忆 | 部分（Memory） | ❌ |
| **安全模型** | 七层纵深防御 | 文件级权限 + Agent 隔离 | 沙箱 + 权限提示 |
| **IDE 集成** | ACP（VS Code/Zed/JetBrains，JSON-RPC） | 无原生 IDE 集成 | VS Code 深度集成 |
| **部署方式** | 自托管（VPS/容器/无服务器） | 自托管（Docker/本地） | 本地安装 |
| **终端后端** | 6 种（Local/Docker/SSH/Modal/Daytona/Singularity） | 本地 + Docker | 本地 |
| **开源协议** | MIT | AGPL-3.0 | 闭源 |

### 7.2 设计哲学差异

**Hermes Agent** 的核心哲学是"**自我进化**"。它不只是一个执行指令的工具，而是一个能从经验中学习、主动创建 Skill、用 RL 训练改进自己的 Agent。它的架构围绕"**一个 AIAgent 类服务所有入口**"设计，平台差异在入口层处理，Agent 核心保持平台无关。

**OpenClaw** 的核心哲学是"**企业集成**"。它深度绑定飞书/企业生态，提供丰富的内置工具和 Skill 系统。架构上更偏向事件驱动和子 Agent 编排，适合需要与企业办公系统深度集成的场景。

**Claude Code** 的核心哲学是"**开发者体验**"。它深度集成 VS Code，只支持 Claude 模型，但提供了最好的 IDE 内 Agent 体验。闭源意味着无法自定义底层行为，但换来了开箱即用的稳定性。

### 7.3 选型建议

| 场景 | 推荐 |
|------|------|
| 需要模型自由度 + 自进化能力 | **Hermes Agent** |
| 需要飞书/企业集成 + 工具丰富度 | **OpenClaw** |
| 只用 Claude + VS Code 深度集成 | **Claude Code** |
| 研究 RL 训练 / 模型微调 | **Hermes Agent**（唯一内置 RL 管线） |
| 多消息平台统一管理 | **Hermes Agent**（18 个适配器） |
| 轻量级个人助手 | 三者均可，看偏好 |

本系列 6 篇文章覆盖了 Hermes Agent 从入门到底层原理的完整路径：
