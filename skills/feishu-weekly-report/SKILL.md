# 飞书多源周报技能

## 快速索引
- 🧭 意图分流与权限确认
- 🗓️ 时间范围动态计算
- 📥 多源拉取（群消息/文档/多维表格/任务）
- 🧹 分类聚合与摘要准则
- 📝 输出模板（个人 vs 项目）
- 📤 写入与回退策略
- ❗ 错误处理与安全限制

## 意图分流
| 用户意图 | 触发词样例 | 路由 | 备注 |
|---------|-------------|------|------|
| 生成周报 | “写周报”、“帮我汇总本周” | → 多源聚合流程 | 默认生成最新周 |

## 前置约束
- 时间格式：ISO 8601（如 `2026-05-26T09:00:00+08:00`），固定时区 `Asia/Shanghai`（UTC+8）。
- 生成内容 ≤ 10,000 字符，最多覆盖 12 周跨度。
- 仅访问当前用户有权限的资源；覆盖写入需明确确认。

---

## 时间范围计算（必须动态）
1. 读取系统当前日期（UTC+8）。
2. 解析用户语义：`本周`、`上周`、`第N周`、显式日期等。
3. 统一回落到“周一 00:00:00”作为起点，“周日 23:59:59”作为终点；若用户要求“截至今天”，则终点为当日当前时间。

| 用户语义 | 起始计算 | 结束计算 | 说明 |
|----------|----------|----------|------|
| 本周 | `currentMonday = today - (weekday-1)` | 当前日期当前时刻 | 若当前为周一，则起止同一天 |
| 上周 | `currentMonday - 7d` | `currentMonday - 1s` | 整周闭区间 |
| 第N周(YYYY-WN) | `WeekDate = ISOWeekToDate(YYYY, N)` 取周一 | 同周周日 23:59:59 | 若跨年，仍以 ISO 周定义 |
| 指定日期范围 | 直接解析用户提供的起止 | 若缺终点→默认起点+6d 23:59:59 | 保证起点≤终点 |

Fallback：若解析失败→提示用户补充“起止日期或周次”，同时给出识别失败原因。

## 数据源清单与采集要点
所有工具调用需带时间范围过滤，若工具不支持则本地过滤。

### 1. 群消息（`feishu_im_user_get_messages`）
```
feishu_im_user_get_messages(
  chat_id="oc_xxx",
  start_time="2026-05-19T00:00:00+08:00",
  end_time="2026-05-25T23:59:59+08:00",
  sort_rule="create_time_desc",
  page_size=50
)
```
- 展开 `thread_id` 以捕捉讨论结论、@我消息、决策记录。
- 提取字段：发送人、时间、主题关键词、行动项。
- Fallback：若 chat_id 失效→提示用户更新；若 API 限流→等待 1s 重试上限 3 次。

### 2. 文档（`feishu_fetch_doc`）
- 支持 doc、sheet、mindnote 等；解析变更时间（若提供 revision 数据）。
- 筛选本周新增段落，提炼成果/结论。
- Fallback：遇到权限报错→提示用户授予访问或提供可共享链接。

### 3. 多维表格（`feishu_bitable_app_table_record`）
```
feishu_bitable_app_table_record.list(
  app_token="xxx",
  table_id="xxx",
  filter={ conjunction: "and", conditions:[{ field_name:"完成时间", operator:"between", value:[startDate, endDate] }] }
)
```
- 提取字段：任务名称、负责人、状态、进度、关联项目。
- 若表中字段缺失→推断默认列名（如“状态”、“进度%”），失败则请求用户映射。

### 4. 任务（`feishu_task_task`）
```
feishu_task_task(action="list", completed=true, page_size=50, start_time=startDate)
```
- 读取完成与未完成任务，优先展示完成项与阻塞项。
- 若任务描述含项目标签，用于后续分组。
- Fallback：API 不支持过滤→全量取回后本地按时间过滤。

> 数据预处理：对不同来源的记录补齐统一字段 `{source, project, type, owner, status, highlights, time}`，并记录原始链接以便追溯。

## 多源聚合流程
1. **确认意图与权限**：复述用户目标、范围、输出形式；若涉及覆盖写入，记录确认结果。
2. **计算时间范围**：调用上述规则，生成 `start_time` / `end_time`，保存为上下文。
3. **并行拉取**：根据用户提供的 chat/doc/表格/任务 ID 列表并行调用；失败的源记录在 `fetch_errors`。
4. **清洗归类**：
   - 去重：同一任务跨来源出现时按优先级（任务 > 表格 > 群聊）合并。
   - 分组：先按项目/主题，再按类型（成果、进行中、问题、风险）。
   - 量化：尽量提取数值（进度%、数量、金额等）。
5. **生成草稿**：套用对应模板（个人/项目），在各段落中填入摘要。
6. **校验与回退**：
   - 若关键段为空（如“成果”无数据）→尝试用进行中或任务摘要补位，并标注“暂无数据”。
   - 若 `fetch_errors` 非空→在输出末尾附“数据缺失说明”。
7. **写入/返回**：按用户指示写入文档或直接返回 Markdown。

## 输出模板

### 个人周报模板
```markdown
# 个人周报（MM/DD - MM/DD）

## ✅ 本周成果
- [成果1] 数据/影响范围
- [成果2]

## 🔄 进行中
- [事项1] 当前状态 + 下一步

## ⚠️ 风险/阻塞
- [风险1] 影响 + 需支持

## 📅 下周计划
- [计划1] 目标 + 时间
```

### 项目周报模板
```markdown
# 项目《项目名称》周报（MM/DD - MM/DD）

## 🎯 里程碑进展
- [阶段/里程碑] 完成度 X%，关键产出

## 📊 项目指标
- 需求完成数：X
- Bug 修复数：Y
- 资源消耗：Z

## 🔄 任务跟进
- [任务/模块] 状态 + 负责人 + 预计完成时间

## ⚠️ 风险与依赖
- [风险] 描述 + 应对策略
- [外部依赖] 进度 + 影响

## 📎 支撑材料
- 群消息、文档、表格链接列表
```
> 规则：若用户未指定，默认个人模板；若检测到多个项目标签或用户指明项目→使用项目模板。

## 写入策略
- 新建文档：`feishu_create_doc(title="周报 - 2026/05/26", markdown=content, folder_token=...)`。
- 追加更新：`feishu_update_doc(doc_id="xxx", markdown=content, mode="append")`；若覆盖写入需再次复述风险并等待确认。
- 用户仅需结果文本→直接在会话中返回 Markdown。

---

## 错误处理与回退
- **时间解析失败**：提示用户提供格式如“2026-05-01 至 2026-05-07”或“2026年第18周”。
- **工具调用失败**：记录失败类型（网络/权限/限流），重试 3 次，每次退避 `2^n * 500ms`；若仍失败→在结果中列出未完成源。
- **数据为空**：尝试放宽过滤（如延长范围或包含进行中任务），仍为空则输出“无数据”占位并标注原因。
- **写入失败**：若 `feishu_create_doc`/`feishu_update_doc` 报错→回退为直接返回 Markdown，并建议用户手动粘贴。
- **用户取消**：立即停止后续操作，返回“已取消，未执行写入”。

---

## 安全与限制
- 不执行删除、批量迁移等危险操作。
- 严禁泄露未授权群聊或文档内容。
- 对历史记录的引用需附来源（群聊消息链接、文档链接或表格记录 ID），但隐藏敏感字段。
- 若用户请求超出 12 周或实时同步→提示不支持并建议分段执行。

以上流程可确保多源聚合、模板化输出与可靠回退，满足个人与项目周报的不同需求。
