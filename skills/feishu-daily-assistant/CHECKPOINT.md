
## Checkpoint 机制（多步骤防重）

### 状态跟踪
```json
{
  "checkpoint": {
    "currentStep": "fetch_messages",
    "completedSteps": [],
    "errors": [],
    "retryCount": 0
  }
}
```

### 步骤定义
| 步骤 | ID | 可重入 | 说明 |
|------|-----|--------|------|
| 意图识别 | classify_intent | ✅ | 无副作用 |
| 获取消息 | fetch_messages | ✅ | 只读 |
| 获取待办 | fetch_tasks | ✅ | 只读 |
| 获取日程 | fetch_calendar | ✅ | 只读 |
| 查忙闲 | check_freebusy | ✅ | 只读 |
| 创建会议 | create_event | ⚠️ | **需幂等检查** |
| 发送消息 | send_message | ⚠️ | **需幂等检查** |

### 写入幂等保障
1. **创建会议**：检查同一时间段是否已有同名日程
   - 已存在 → 返回已有日程，不重复创建
   - 不存在 → 正常创建
2. **发送消息**：检查最近是否已发送相同内容
   - 已发送 → 跳过，返回"已发送"
   - 未发送 → 正常发送

### 断点恢复
- 只读操作（消息/待办/日程）：失败后直接重试，无副作用
- 写操作（会议/消息）：失败后检查是否已部分执行
  - 会议已创建但未邀请参会人 → 补充邀请
  - 消息已发送但未确认 → 检查发送状态
