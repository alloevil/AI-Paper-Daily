## 一、架构概览

> 基于论文《Automating Supply Chain Disruption Monitoring via an Agentic AI Approach》（arXiv:2601.09680, Cambridge, 2026）的 7 代理 4 阶段架构，结合小米半导体数据现状 + OpenClaw 平台能力设计。

### 1.1 论文架构：7 代理 4 阶段流水线

```
┌─────────────────────────────────────────────────────────────────┐
│                    4 阶段流水线                                   │
│                                                                 │
│  Stage 1          Stage 2          Stage 3         Stage 4      │
│  事件检测          相关性过滤        网络映射+风险评估   缓解+报告   │
│  ┌──────┐        ┌──────┐        ┌──────┐        ┌──────┐      │
│  │ ①中断│──→──→──│ ③实体│──→──→──│ ④网络│──→──→──│ ⑥缓解│      │
│  │ 检测 │        │ 识别  │        │ 映射  │        │ 方案  │      │
│  │ ②中断│        │      │        │ ⑤风险│        │ ⑦报告│      │
│  │ 分类  │        │      │        │ 评估  │        │ 生成  │      │
│  └──────┘        └──────┘        └──────┘        └──────┘      │
└─────────────────────────────────────────────────────────────────┘
```

**7 个专业代理**：

| 代理 | 阶段 | 职责 | 映射到我们的实现 |
|------|------|------|----------------|
| ① 中断检测代理 | Stage 1 | 从新闻/RSS/API 检测中断事件 | chainsentry_ai MCP + web_access_tool |
| ② 中断分类代理 | Stage 1 | 分类（地缘政治/自然灾害/贸易限制/需求冲击/监管变化） | LLM 分类 |
| ③ 实体识别代理 | Stage 2 | 识别受影响的公司和实体 | LLM NER + 公司名字典 |
| ④ 网络映射代理 | Stage 3 | 将中断映射到多层供应商网络 | Neo4j 图查询 |
| ⑤ 风险评估代理 | Stage 3 | 基于网络结构评估暴露程度 | 7 维度事实分析 |
| ⑥ 缓解方案代理 | Stage 4 | 推荐替代采购等缓解措施 | ⚠️ 能力边界外 |
| ⑦ 报告生成代理 | Stage 4 | 生成可操作的情报报告 | 飞书文档/消息输出 |

### 1.2 论文安全机制（三层防护）

| 层 | 机制 | 我们的实现 |
|---|------|----------|
| RAG 接地 | 所有事实性声明必须与知识图谱验证 | Neo4j 图数据 + chainsentry_ai |

### 2.3 增量同步

不要全量重建。记录每行的 hash，只同步变化的行。

```python
import hashlib, json

def compute_row_hash(row: dict) -> str:
    canonical = json.dumps(row, sort_keys=True, ensure_ascii=False)
    return hashlib.md5(canonical.encode()).hexdigest()

def incremental_sync(sheet_data: list[dict], db_hashes: dict[str, str]):
    """
    sheet_data: 飞书表读出的最新数据
    db_hashes: Neo4j 中已有的 {行ID: hash}
    返回: (新增, 变更, 删除)
    """
    current_hashes = {}
    for row in sheet_data:
        row_id = row["物料编号"]
        current_hashes[row_id] = compute_row_hash(row)

    added = [r for r in sheet_data if r["物料编号"] not in db_hashes]
    deleted = [rid for rid in db_hashes if rid not in current_hashes]
    changed = [
        r for r in sheet_data
        if r["物料编号"] in db_hashes
        and current_hashes[r["物料编号"]] != db_hashes[r["物料编号"]]
    ]
    return added, changed, deleted
```

变更日志示例：
```
2026-04-29 09:00 同步变更日志
├─ 新增: 物料 X001 (RF前端模组)
├─ 变更: 物料 M320 封装厂 立讯→华天
├─ 变更: 物料 P105 采购占比 博通 60%→67%
└─ 删除: 无
```

### 2.4 Schema 校验（同步前）

每次同步前先校验，不通过则报警不入库：

```python
VALIDATION_RULES = {
    "物料编号": {"required": True, "type": "string"},
    "供应商":   {"required": True, "type": "string", "max_empty_rate": 0},
    "晶圆厂":   {"required": False, "type": "string", "max_empty_rate": 0.15},
    "封装厂":   {"required": False, "type": "string", "max_empty_rate": 0.20},
    "测试厂":   {"required": False, "type": "string", "max_empty_rate": 0.20},
}

def validate_data(rows: list[dict]) -> dict:
    report = {"total": len(rows), "errors": [], "warnings": []}
    for field, rules in VALIDATION_RULES.items():
        values = [r.get(field) for r in rows]
        empty_count = sum(1 for v in values if v is None or v == "")
        empty_rate = empty_count / len(values) if values else 0

        if rules.get("required") and empty_count > 0:
            report["errors"].append(f"必填字段 '{field}' 存在 {empty_count} 个空值")
        if "max_empty_rate" in rules and empty_rate > rules["max_empty_rate"]:
            report["warnings"].append(
                f"'{field}' 空值率 {empty_rate:.0%} 超过阈值 {rules['max_empty_rate']:.0%}"
            )
    return report
```

| 节点类型 | 数据来源 | 示例 | 说明 |
|---------|---------|------|------|
| **物料(MPN)** | D 列 | 1010201000537A | 图的中心节点 |

### 3.2 边的关系

| 边类型 | 从 → 到 | 含义 | 数据来源 |
|--------|---------|------|---------|
| **供应** | 供应商 → 物料(MPN) | 供应商供应这个物料 | F → D |
| **晶圆制造** | 物料(MPN) → 晶圆厂 | 这个物料由谁做晶圆 | D → I |
| **封装** | 物料(MPN) → 封装厂 | 这个物料由谁封装 | D → M |
| **测试** | 物料(MPN) → 测试厂 | 这个物料由谁测试 | D → Q |
| **位于** | 工厂 → 国家/省市 | 工厂所在地理位置 | I→J/K/L, M→N/O/P, Q→R/S/T |
| **用于** | 物料(MPN) → 业务线 | 这个物料用于什么产品线 | D → H |
| **采购** | 小米 → 供应商 | 小米向谁采购 | F |

### 3.3 关系示意

```
                        ┌──[供应]──→ 供应商(博思達)
                        │
                        ├──[晶圆制造]──→ 晶圆厂(威讯联合) ──[位于]──→ 美国
小米 ──[采购]──→ 供应商 ──→ 物料(MPN) ─┤
                        ├──[封装]──→ 封装厂(立讯) ──[位于]──→ 北京
                        │
                        ├──[测试]──→ 测试厂(立讯) ──[位于]──→ 北京
                        │
                        └──[用于]──→ 业务线(手机)
```

### 3.4 注意事项

- **供应商 和 晶圆厂/封装厂/测试厂 可能是同一家公司**（如立讯既是供应商又是封装厂），图里作为不同节点，通过边连接
- **二级料的封装厂/测试厂有多个**（"/"分隔），建图时拆成多条边（一对多关系）
- **晶圆→封装→测试 是固定顺序**（物理工艺决定），但图里不需要显式的顺序边，因为都是从物料(MPN)出发
- **公司名消歧**：同一公司可能有不同写法，需维护公司名标准化字典

| 别名 | 标准名 |

### 3.6 空值处理

| 字段为空 | 处理方式 |
|---------|---------|
| A/B/C/E/G 列 | 跳过（不建节点） |
| I 晶圆厂为空 | 跳过"晶圆制造"边 |

多行可能有相同的供应商/晶圆厂/封装厂，建图时用 **MERGE**（有则复用，无则创建）：

**执行流程**：
```

  ├── 股权/财报/新闻 → 查 MCP（chainsentry_ai）
```

## 五、查询引擎（三层架构）

| 层级 | 触发条件 | 示例 | 可靠性 |
|------|---------|------|--------|
| L1 精确模板 | 意图命中预定义模式 | "XX物料的供应链" | ✅ 100% |
| L2 参数化模板 | 意图命中但参数需提取 | "美国晶圆厂相关的手机物料" | ✅ 95% |
| L3 LLM 生成 | 前两层都不命中 | "哪些供应商同时覆盖手机和汽车" | ⚠️ 70-80% |

### 5.1 L1 精确模板库

```python
TEMPLATES = {
    "物料供应链": {
        "patterns": ["{物料}的供应链", "{物料}供应商是谁", "谁供应{物料}"],
        "cypher": """
            MATCH (m:Material {name: $物料})
            OPTIONAL MATCH (m)<-[:SUPPLIES]-(s:Supplier)
            OPTIONAL MATCH (m)-[:WAFER_FAB]->(w:WaferFab)
            OPTIONAL MATCH (m)-[:PACKAGED_BY]->(p:Packaging)
            OPTIONAL MATCH (m)-[:TESTED_BY]->(t:TestHouse)
            OPTIONAL MATCH (w)-[:LOCATED_IN]->(wc:Country)
            OPTIONAL MATCH (p)-[:LOCATED_IN]->(pc:Country)
            OPTIONAL MATCH (t)-[:LOCATED_IN]->(tc:Country)
            RETURN m.name AS 物料, s.name AS 供应商,
                   w.name AS 晶圆厂, wc.name AS 晶圆厂国家,
                   p.name AS 封装厂, pc.name AS 封装厂国家,
                   t.name AS 测试厂, tc.name AS 测试厂国家
        """,
        "confidence": 1.0,
    },
    "供应商覆盖": {
        "patterns": ["{供应商}供应哪些物料", "{供应商}的产品线"],
        "cypher": """
            MATCH (s:Supplier {name: $供应商})-[:SUPPLIES]->(m:Material)
            RETURN s.name AS 供应商, collect(m.name) AS 物料列表, count(m) AS 物料数量
        """,
        "confidence": 1.0,
    },
    "独供物料": {
        "patterns": ["独供物料有哪些", "单一供应商物料", "独供风险"],
        "cypher": """
            MATCH (m:Material)<-[:SUPPLIES]-(s:Supplier)
            WITH m, collect(s) AS suppliers
            WHERE size(suppliers) = 1
            RETURN m.name AS 物料, m.category AS 品类, suppliers[0].name AS 唯一供应商
        """,
        "confidence": 1.0,
    },
    "品类集中度": {
        "patterns": ["{品类}的供应商集中度", "{品类}采购占比"],
        "cypher": """
            MATCH (m:Material {category: $品类})<-[:SUPPLIES]-(s:Supplier)
            RETURN s.name AS 供应商, count(m) AS 覆盖物料数
            ORDER BY 覆盖物料数 DESC
        """,
        "confidence": 1.0,
    },
    "地缘分布": {
        "patterns": ["{品类}晶圆厂分布", "{品类}的地缘风险"],
        "cypher": """
            MATCH (m:Material {category: $品类})-[:WAFER_FAB]->(w:WaferFab)-[:LOCATED_IN]->(c:Country)
            RETURN c.name AS 国家, count(w) AS 工厂数量, collect(DISTINCT w.name) AS 涉及工厂
            ORDER BY 工厂数量 DESC
        """,
        "confidence": 1.0,
    },
    "供应商地理": {
        "patterns": ["{供应商}的工厂在哪些国家", "{供应商}的地缘分布"],
        "cypher": """
            MATCH (s:Supplier {name: $供应商})-[:SUPPLIES]->(m:Material)
            OPTIONAL MATCH (m)-[:WAFER_FAB]->(w:WaferFab)-[:LOCATED_IN]->(wc:Country)
            OPTIONAL MATCH (m)-[:PACKAGED_BY]->(p:Packaging)-[:LOCATED_IN]->(pc:Country)
            OPTIONAL MATCH (m)-[:TESTED_BY]->(t:TestHouse)-[:LOCATED_IN]->(tc:Country)
            RETURN s.name AS 供应商,
                   collect(DISTINCT wc.name) AS 晶圆厂国家,
                   collect(DISTINCT pc.name) AS 封装厂国家,
                   collect(DISTINCT tc.name) AS 测试厂国家
        """,
        "confidence": 1.0,
    },
}
```

## 六、品类风险分析

### 6.1 品类风险定义

品类风险 = 衡量某个品类（如射频、基带、内存）的整体供应安全程度，从 7 个维度综合评估。

### 6.2 维度定义

| 维度 | 含义 | 数据来源 | 收集方式 |
|------|------|---------|---------|
| **独供率** | 品类中只有 1 个供应商的 PN 占比 | 采购数据 | 需整理 |
| **供应商集中度** | Top1 供应商采购额占品类总采购额比例 | 采购数据 | 需整理 |
| **地缘暴露率** | 关键制造环节在高风险国家的占比 | 半导体汇总表 | 直接统计 |
| **替代难度** | 同品类有几家可选供应商 | 半导体汇总表 | 直接统计 |
| **财务健康度** | 品类中供应商财报评级 C/D 的占比 | chainsentry_ai | 实时查询 |
| **股权异常** | 品类中近期有股权变更的供应商数 | chainsentry_ai | 实时查询 |
| **近期事件** | 品类中近 7 天有中断事件的供应商数 | chainsentry_ai | 实时查询 |

### 6.3 原则：事实优先，评分靠后

**第一版只做事实陈述，不做评分。** 让业务人员自己判断风险等级。

#### 输出格式

```markdown
## 📊 射频品类风险概况

### 供应结构
- 物料总数: 20个
- 独供物料: 3个 (15%)
- 最大供应商: 博思達 (占比 70%)

### 地缘分布（晶圆厂）
| 国家 | 占比 | 供应商 |
|------|------|--------|
| 美国 | 60% | 博思達、Qorvo |
| 台湾 | 30% | 稳懋 |
| 韩国 | 10% | 三星 |

### 供应商财务健康
| 供应商 | 最新评级 | 来源 | 更新时间 |
|--------|---------|------|---------|
| 博思達 | B | chainsentry_ai | 2026-Q1 |
| Qorvo | A- | chainsentry_ai | 2026-Q1 |

### 近期事件
| 供应商 | 事件 | 时间 | 影响 |
|--------|------|------|------|
| 博思達 | 工厂扩建停产 | 2026-04-20 | 可能影响 Q2 交期 |

---
💡 以上为事实数据，风险等级请结合业务判断。
```

### 6.4 如果业务要求评分：建议权重 + 敏感性分析

| 维度 | 权重 | 理由 |
|------|------|------|
| 独供率 | **25%** | 独供是最高风险，一断全断 |
| 供应商集中度 | **20%** | 集中度高 = 替代难 |
| 地缘暴露率 | **20%** | 地缘政治是当前最大变量 |
| 替代难度 | **15%** | 有备选 = 风险可控 |
| 财务健康度 | **10%** | 财务差 = 供应不稳 |
| 股权异常 | **5%** | 关注但非决定性 |
| 近期事件 | **5%** | 短期信号，权重不宜过高 |

**综合评分**：加权平均，输出 0~100 分。
**风险等级**：HIGH ≥ 70 / MEDIUM 40~69 / LOW < 40

**必须同时展示敏感性**：
```markdown
当前评分: 72 (高风险)
权重调整影响:
  - 独供率权重 ±5%: 评分范围 68 ~ 76
  - 地缘权重 ±5%: 评分范围 67 ~ 77
结论: 无论权重如何调整，该品类始终在高风险区间 → 结论稳健
```

### 7.1 渐进式回答

用户问"博通的风险怎么样？"时，分步回答：

```
博通供应链结构：

└─ 独供物料: 3个
```

**第二步：外部信息补充（秒级，可 spawn 并行查）**
```
博通外部信息（来源: chainsentry_ai）：
├─ 最新财报评级: B (2026-Q1)
├─ 近期新闻: 无重大风险事件
└─ 股权结构: 无异常变动
```

**第三步：综合概况**
```
综合评估：中等关注
├─ 结构性风险: 独供3个物料 → 需关注
├─ 地缘风险: 晶圆在美国+台湾 → 分散度尚可
└─ 财务风险: B级 → 正常范围
```

如果 chainsentry_ai 挂了，第 1 步的结果照样能给出来，不至于整个查询失败。**降级而非崩溃。**

### 7.2 结果置信度标签
