# 项目进度跟踪器

## 1. 使用概览

- 目标：在飞书生态内快速获取项目表、项目文档与讨论信息，输出进度汇总、风险清单、阻塞分析。
- 所有工具均以**用户身份**调用：`feishu_bitable_app_table_record`、`feishu_fetch_doc`、`feishu_im_user_search_messages`、`feishu_search_doc_wiki`。
- 只读模式：严禁写入、删除或批量操作。
- 时间格式：ISO 8601，时区固定为 Asia/Shanghai (UTC+8)。

## 2. 前置配置与数据源优先级

1. **显式参数**：用户直接提供 `app_token` + `table_id` 或文档 URL。
2. **记忆检索**：从 `MEMORY.md` 或历史对话中回溯。
3. **文档搜索**：使用 `feishu_search_doc_wiki` 搜索项目关键字（限定项目名称/里程碑）。
4. 若以上全部缺失 → 明确告知用户并退出。

## 3. 项目表字段自动映射

当表结构未知时，构建字段语义映射：
1. 读取 `feishu_bitable_app_table_record` 的 `fields_meta`（若可用）并按以下优先级匹配：
   - 任务名：`['标题','任务名','Name','Subject']`
   - 状态：`['状态','进度','Status']`
   - 负责人：`['负责人','Owner','Assignee']`
   - 截止时间：`['截止时间','Due','Deadline']`
   - 优先级：`['优先级','Priority']`
   - 阶段：`['阶段','Phase','Sprint']`
2. 未直接匹配时，使用关键词+字段类型规则：
   - 文本列含“任务/标题/事项” → 任务名
   - 单选/多选列含“状态/进度” → 状态
   - 人员列 → 负责人
   - 日期列含“截止/到期” → 截止时间
3. 将映射结果缓存到上下文，后续步骤统一引用；若字段缺失，记录告警并在输出中提示人工确认。

## 4. 意图分流与总流程

| 用户意图 | 典型问题 | 路由 |
|----------|----------|------|
| 进度汇总 | “项目进展如何”“目前状态” | 路由 1 |
| 风险识别 | “有什么风险”“会不会延期” | 路由 2 |
| 阻塞分析 | “谁在卡”“阻塞在哪” | 路由 3 |

通用步骤：
1. 获取或确认数据源（第 2 节）。
2. 运行字段映射（第 3 节）。
3. 拉取项目表数据 (`feishu_bitable_app_table_record.list`)；必要时分页汇总。
4. 可选：
   - `feishu_fetch_doc` 读取项目 Wiki / PRD 提取里程碑、依赖描述。
   - `feishu_im_user_search_messages` 检索本周讨论，捕捉沟通阻塞。
5. 进入对应路由输出模板。

## 5. 路由 1：进度汇总

### 数据抓取

```
feishu_bitable_app_table_record.list(
  app_token,
  table_id,
  filter={ conjunction: 'or', conditions: [
    {field_name: 状态, operator: 'isNot', value: ['已完成']},
    {field_name: 状态, operator: 'isNot', value: ['已取消']}
  ]},
  sort=[{field_name: 截止时间, desc: false}]
)
```

### 汇总逻辑

- 统计：总任务 / 已完成 / 进行中 / 未开始，计算完成率 = 已完成 ÷ 总任务。
- 里程碑：从文档中提取日期 + 状态；若缺失则标记“未提供”。
- 讨论摘要：按消息时间排序，保留最近 5 条含行动项的对话。

### 输出建议

```
📊 项目进度
- 整体进度：72% (18/25)
- 关键里程碑：里程碑 A 6/01 ✅；里程碑 B 6/15 ⏳
- 本周亮点：…
- 未完成重点：任务 X (负责人A，截止 5/30)
```

## 6. 路由 2：风险识别（规则引擎）

构建规则引擎，对每条任务计算风险标签与等级，可多标签并存：

| 规则 | 条件 | 权重 | 自动建议 |
|------|------|------|----------|
| 超期 | `截止时间 < 今天` 且 状态≠已完成 | 5 | 提示“即刻处理，汇报延期理由” |
| 即将到期 | `0 ≤ 截止时间-今天 ≤ 2` 天 | 3 | 提醒负责人确认缓冲 |
| 进度停滞 | `last_update > 7 天` 或状态 7 天未变 | 3 | 建议每日站会追踪 |
| 依赖阻塞 | 依赖字段指向任务状态非完成 | 4 | 列出阻塞链（A→B→C） |
| 人员过载 | 负责人进行中任务数量 > 3 或 超期任务 ≥2 | 4 | 建议任务分摊 |

执行步骤：
1. 从表中解析 `last_update`（如无则用消息时间或文档更新时间估算）。
2. 若存在依赖字段（关系/文本），解析成图结构，递归查找阻塞链。
3. 计算总风险分（∑权重），≥5 归为高风险，3-4 为中风险，<3 为低风险。

输出模板：
```
⚠️ 风险雷达
🔴 高风险
- 任务A：超期3天 + 依赖任务C未完成 → 总分9
🟡 中风险
- 任务D：即将到期 + 负责人过载 → 总分6
💡 建议
- 任务A：与负责人X同步，确认补救计划
- 任务D：评估能否拆分或转派
```

## 7. 路由 3：阻塞分析（多维度）

从四个维度输出：
1. **任务维度**：列出当前阻塞链、被阻塞的后续任务、持续天数。
2. **人员维度**：每位成员的任务数、超期数、回复滞后度（来自讨论消息时间）。
3. **依赖维度**：基于依赖图，找出关键路径与最长阻塞链，标记根因任务。
4. **沟通维度**：分析 `feishu_im_user_search_messages` 中的未回应话题（>48 小时无响应）或重复询问。

输出示例：
```
🔍 阻塞分析
任务阻塞：任务A 超期3天 → 阻塞任务B/C
人员瓶颈：张三持有5任务，其中2超期；信息在 48h 未回复
依赖链：A→C→D，根因 A 未获审批
沟通卡点：群内审批请求 5/24 提出后无回应
建议：安排审批会议；为张三减负；并行推进 C 的准备工作
```

## 8. 错误处理与回退

- **数据缺失**：若字段映射失败或必填字段为空，立即回退到上一步，提示用户提供字段名，再次运行映射。
- **接口报错**：捕获 `feishu_*` API 错误码，若为权限/速率限制，延迟重试一次；若持续失败，输出“需用户授权/稍后重试”。
- **依赖解析失败**：若依赖字段格式异常，记录原始内容，回退到仅按任务状态输出风险。
- **消息检索为空**：提示“最近 X 天无沟通记录”，并仅输出任务/依赖结论。
- 所有回退路径需记录在最终汇报的“分析局限”段落内，防止误解。

## 9. 安全与限制

- 始终保持只读，不上传/同步任何内容。
- 仅访问用户有权限的飞书资源。
- 风险与阻塞结论基于规则推断，需鼓励用户复核。
- 输出中避免泄露非必要的个人信息，只展示与任务直接相关的责任人。
